# Product

## Who is this for?

**Bali Project** is built for three audiences:

| Audience | How they use it |
|---|---|
| **Developers** (beginner to intermediate) | A clean, native-PHP codebase to learn from, maintain, and extend |
| **Tourism administrators** | A simple admin dashboard to manage destinations, bookings, and content |
| **Public visitors** | A polished portal to research destinations, transport, tickets, and accommodation |

## Product Purpose

Bali Project provides a native-PHP foundation for a Bali tourism portal that is easy to run locally, easy for new developers to understand, and can evolve incrementally into a fuller booking and administration platform.

**Success means:**

- The project runs without heavy setup.
- The file structure is easy to understand.
- Core pages feel professional and load fast.
- New features can be added without breaking existing ones.

## Brand Personality

**Clean, calm, premium tropical.**

Language and visuals should feel tidy, modern, professional, and uncluttered. The Bali identity is carried through photography, teal/tropical color, sunset accents, generous spacing, and subtle interactions.

## Anti-References

- Overcrowded layouts with too many competing colors.
- Legacy template patterns with heavy inline CSS and duplicated navigation.
- Excessive visual effects that hurt readability.
- Stacked cards with no hierarchy.
- Raw database errors or technical messages shown to end users.

## Design Principles

1. **Stability first** — stability matters more than large-scale refactoring.
2. **Premium public pages** — public pages must feel premium, lightweight, and easy to scan.
3. **Functional admin** — admin panels and forms should be dense, clear, and distraction-free.
4. **Backward compatibility** — preserve existing URLs unless a migration plan exists.
5. **Privacy by default** — non-public files must be treated as private even on shared hosting.

## Accessibility & Inclusion

Target at least **WCAG AA** for text contrast and form controls. Animations should be subtle and respect `prefers-reduced-motion`. Navigation, buttons, forms, empty states, and error states must be clear without relying on color alone.
